# Foli phase 5 — hardening, measured regression and handoff

The release adds real repository/encryption/security integration tests for HOLDER, OFFICER and ADMIN; source replacement/deletion/role changes invalidate access and results. A damaged or missing original is never automatically repaired. Private HTTP concurrency is bounded in addition to the job queue; completed jobs are evicted safely rather than wedging the 32-result limit.

PDF opening actions remain inert, attachments/XFA receive explicit warnings, and form widgets trigger OCR. Oversized image resources, recursive/nested forms, columns and tiny print are handled with resource checks or uncertainty. Production parsing and original-page rendering now run in a separate 512 MiB child JVM with a wall-clock limit, bounded pipe output, cancellation/descendant termination and per-job scratch cleanup. The child inherits no application credentials and starts no Spring/DB/model context. It is resource isolation rather than a full OS sandbox.

Real end-to-end evaluation exposed model source-reference errors despite exact string alignment. Retrieval now discounts repeated page boilerplate, prioritizes requested clause headings and returns compact per-answer evidence IDs. The verifier accepts only current permitted spans, omits invented references/quotations and removes citations from explicit abstentions. No model-derived claim is promoted to an authoritative fact. The failed and interrupted runs are retained separately from the final completed corpus.

The final Java gate runs **72 tests**, including real OCR, real child JVMs and actual local inference with non-loopback Java connections denied. Django passes **63**, the independent Node proof verifier/UI passes **22**, and the actual Solidity/Ganache gate passes. Existing live wallet workflow/security gates pass **51/23** checks without Foli changes to their implementation. Real Foli reading passes **26** checks and final injection/authorization/DB/chain/log safety passes **19**. The final real Edge browser run passes **18**, with zero JavaScript exceptions or external requests. The packaged Boot JAR reader is also executed successfully.

The completed application corpus achieved **78/80 strict rubric passes**, including 58/60 document cases and all unavailable-fact, write-request and general-chat cases. All returned quotes aligned exactly. The two strict misses remain recorded, including an alternate valid cancellation passage outside the gold page label. Final whole-document review found **40/40** critical passages with **125/125** successful semantic chunks in **19.866 seconds**.

The seven-file reader benchmark measures clean/rotated scan OCR errors, mixed content, column warnings, unreadable pages and exact TXT/CSV preservation. Both clean printed OCR gold samples had zero normalized character/word errors; this is a narrow synthetic sample. Four real model packages and CPU-only inference were measured, with digests, licenses, package bytes, cold/warm timings, token throughput, native runner RAM and model VRAM. A real Ollama process outage returned ERROR/OFFLINE without fallback; the exact launcher restored READY and actual inference successfully. See [the final evaluation](FOLI_EVALUATION_2026-10-15.md) for achieved results, source-support misses, scope and negative evidence.

The OCR environment has a checked-in 31-package explicit Windows lock, verified by an offline dry run; runtime setup retains receipts and succeeds idempotently. No application startup downloads models. Dependency/license details are in [the inventory](FOLI_DEPENDENCIES_2026-10-15.md). Exact service commands and controls are in [the runbook](FOLI_IMPLEMENTATION.md), and [the demonstration](FOLI_DEMO.md) provides the complete browser flow with real local captures and synthetic credentials kept outside Git.

Physical adapter disconnection, comprehensive native-process OS egress isolation, real-world legal validation and broad handwriting/multilingual OCR evaluation remain unperformed. Read-only model/tool boundaries, loopback transport, disabled Ollama cloud mode and source authorization are enforced in code and covered by real tests. These distinctions are retained in the handoff.

Only the existing `cf` branch is changed. Original selective-disclosure, contracts, sharing and receiver implementation files remain unchanged except the private navigation/routing/logging integration described in phase 4. No remote push, main modification, reset or merge was performed. Retained runtime state and prior artifacts were preserved; old regression output files were copied before repeat tests generated new evidence.
