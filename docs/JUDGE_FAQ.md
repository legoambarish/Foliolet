# Judge questions and honest answers

**What does PASS prove?** The disclosed typed claims match their Merkle commitment, the locally governed test issuer has the right scope, lifecycle and freshness satisfy this signed request, and the bound holder key authorized this audience and nonce. It does not prove the real-world statement is true.

**Who recognizes the university?** The pinned governance account recognizes a simulated issuer address for a claim type. This local chain is not an independent institutional registry. Production onboarding and external authority evidence are outstanding.

**Can conversion improve assurance?** No. Unsigned uploads and mock imports remain self-asserted. A pinned, cryptographically valid supported XML source is classified separately. Native test issuance is a different evidence class; imported review never promotes it.

**Why blockchain?** The implementation brief requires EVM governance, immutable commitments, revocation and supersession. The report recommended an optional chain and a TypeScript/SD-JWT stack. This build deliberately retains Spring, Django, PostgreSQL and the custom salted-Merkle/EIP-712 protocol. It makes no SD-JWT, OpenID or ZK conformance claim.

**Can a verifier reproduce a decision without Foliolet?** Yes, using the independent reader, separately pinned roots, saved package, signed decision and chain access to the recorded block. Current reliance requires current chain evidence. No chain access means UNKNOWN, not a fabricated fresh PASS.

**Can you erase a downloaded disclosure?** No. Server expiry, one opening and revocation control further server release. A recipient can copy bytes already received. Retention is a stated recipient commitment, not remote erasure.

**Can the model share or approve?** No. Local AI sees bounded untrusted source text and has no action tools. Its candidate is validated against the exact selected request. Execution requires the holder's EIP-712 approval and presentation signatures.

**Do citations guarantee correctness?** No. Exact quote validation prevents fabricated quotations from reaching the UI, but a real quote can support a bad interpretation. Assistance is labeled unverified and never becomes evidence, policy, factual truth or a legal conclusion.

**Is DigiLocker connected?** The optional Setu sandbox adapter follows the documented API. No authorized live provider session was available or exercised. Real issued XML schemas and authority chains remain unsupported until validated. A mock or DigiLocker filename proves nothing about origin.

**Is the NFC sticker a secure wallet?** No. A static NDEF URL is clonable discovery transport. It contains no protected facts or holder key and cannot approve a disclosure. Physical phone tapping was not tested because hardware was unavailable.

**Is this production ready?** No. Demo issuer keys are backend custodial public test keys, browser custody needs stronger operational controls, Ganache has unpatched development dependencies, Docker execution is unverified on this host, and real issuer/provider onboarding is incomplete. The implemented trust boundary is testable without making a production certification claim.
