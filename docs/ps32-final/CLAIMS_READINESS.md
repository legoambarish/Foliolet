# Claims register and readiness decision

Read [FINAL_ACCEPTANCE.md](FINAL_ACCEPTANCE.md) for the latest executed source revisions and outcomes. Earlier failed runs remain in [EVIDENCE.md](EVIDENCE.md). This is an engineering judgment, not a guarantee of placement or organizer eligibility.

## Decision

**Ready for a controlled, fictional-data, local PS32 demonstration of the tested workflow, subject to a rehearsal on the actual presentation machine. Not certified for production, universal document accuracy or issuer-authenticated credential acceptance.**

The core evidence is a real browser-to-proof workflow, independent proof tamper rejection, actual PostgreSQL single-use concurrency, preserved-state database/EVM/backend recovery, source-association red/green tests, encrypted sessions, explicit private-cloud denial and a real signed/unsigned/tampered PDF inspection flow. The strongest unresolved competition risk is positioning: a valid commitment still does not prove an untrusted source is genuine. Explain that directly rather than trying to hide it behind blockchain or AI.

The final acceptance register must show the latest tested dependency set. Do not silently treat an earlier green run as proof that a later untested code change works. Documentation-only commits are distinguished from application changes.

## Claims requiring explicit qualifications

**99.41% recall / 98.82% precision:** only the 14 fictional PDFs and 169 labelled facts, including review-required suggestions, under the recorded Linux test conditions. There were two incorrect review suggestions and no false automatic suggestions. The audit preserved the repaired baseline's score; it did not increase it.

**Real-world document evaluation:** eight public CC-BY-4.0 CORD receipts were executed with original human annotations. On six held-out total targets, four matched as normalized decimals, a fifth had the correct source literal but unsupported currency normalization, and one was wrong. Every emitted suggestion required review. These results are not Indian academic accuracy.

**Local AI works:** the actual model ran offline and the actual Foli/Spring-AI transport passed three focused cases. The strict 10-case answer/citation rubric passed only five cases. The model is optional assistance, not verification authority or reliable autonomous decision-making.

**Offline processing:** local source inspection and the network-isolated model experiment were demonstrated. Online chain/status freshness requires the appropriate reachable service. Cached mathematical validity is not proof of current nonrevocation.

**Cross-platform:** Linux full-stack and Windows Django/PowerShell parsing were executed. Windows had one platform-specific skipped test. A complete Windows PostgreSQL/EVM hardware deployment and macOS startup were not executed here.

**Dependency remediation:** specific resolved Java and Python versions were patched and queried against advisory feeds. Ganache's npm tree retains known advisories. Zero feed matches for a selected environment, where observed, does not mean the application has no vulnerabilities.

## Claims we must not make

Do not claim that Foliolet verifies every issuer, that a DigiLocker logo or arbitrary QR proves issuance, or that a valid self-signed PDF is a university-authenticated credential. Do not call platform signing holder-controlled signing. Do not call a committed threshold assertion a zero-knowledge proof.

Do not claim a single-operator Ganache demo is fully decentralized or production-secure. Do not say that no competitor has selective disclosure or blockchain credentials. Do not claim W3C VC/SD-JWT/OpenID4VP interoperability without implementing and testing the applicable profiles.

Do not claim universal OCR accuracy, hallucination-free AI, total prompt-injection immunity, exhaustive vulnerability discovery, unlimited scaling, deletion of already disclosed information, authenticated recipients from an audience label, NFC copy protection, or actual physical-device tests that did not run.

Do not imply institutional partnerships, government API approval, paying customers, independently measured commercial savings or organizer approval that were not established. Pre-existing code must be disclosed honestly; exact current eligibility rules were not independently verified.

## Remaining blockers by intended use

### Before presenting on the actual laptop

Rehearse the native fictional PDF, source review, confirmation, anchoring, selected proof and tamper rejection on the exact demonstration revision. Confirm the retained deployment pins and keys. Keep the core route independent of internet and optional Ollama. Use the signature inspector only on supported fixtures. Physical NFC or a public receiver should be shown only after real device/network rehearsal; otherwise use the verified local browser path.

These are presentation-machine checks, not an excuse to replace the executed repository tests with an untested plan. The [runbook](DEMO_RUNBOOK.md) contains the actual supported setup and failure boundaries.

### Before any production or institutional reliance

Resolve the Ganache/development infrastructure gap and remaining dependency exposure; harden web deployment, authentication, rate limits, backups, secrets and OS-level document isolation; define issuer authority and revocation policies; obtain a consented, independently labelled academic corpus; validate workload-wide resource limits and all SQL/EVM/file reconciliation boundaries; remove or segregate legacy plaintext behavior.

### Deferred by evidence, not concealed

No actual mobile/NFC device, live Cloudflare tunnel, full macOS run, full Windows service lifecycle, genuine trusted Indian issuer credential, broad malicious-PDF fuzz campaign, production load distribution or general academic-accuracy estimate was established. These remain explicitly outside acceptance. No private document was uploaded to a hosted provider to compensate for those gaps.

## Recommended final positioning

**“Share the fact, not the file—and see exactly what has been verified.”**

Show source support, holder modification, commitment integrity, lifecycle status and issuer authority as separate questions. Demonstrate a changed proof being rejected and a mathematically valid self-signature remaining issuer-untrusted. The project is more credible and competitive with those honest boundaries than with a larger set of unsupported features.
